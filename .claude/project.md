## 環境構成（DB / Clerk）

コード・docs から読み取れない運用情報。破壊的操作の可否判断に直結する。

| 環境 | DB | Clerk インスタンス |
|------|----|------------------|
| ローカル開発・テスト | ローカル/テスト用 Neon（**本番とは別**） | 開発インスタンス（`pk_test_` / `sk_test_`） |
| 本番 | 本番 Neon（**実在する**） | 本番インスタンス（`pk_live_` / `sk_live_`） |

- **本番の接続情報はローカルに存在せず、Vercel の環境変数にしかない。** これが本番への誤操作に対する最も強い防御である
- シードのテストユーザー（`bonjiri@example.com` 等）は**開発インスタンスにのみ存在する**。本番 Clerk には存在しないため本番にサインインできず、本番 DB にシードユーザー行が作られることはない
- Clerk の開発インスタンスとテストユーザーは **daily-hub / link-hub と共有している**。`SEED_PASSWORD` の変更は 3 リポジトリに波及するため、値の変更は揃えて行う
- `prisma/seed.ts` は `CLERK_SECRET_KEY` が `sk_test_` であることを要求する。本番インスタンスが `sk_live_` であるため、このガードは本番 Clerk への誤操作を確実に止める
